# A worked example

This fictional example illustrates the complete loop. The reactions and results are invented, not evidence from a user trial.

## Understand

The user says, “I want an AI coding partner, but I don't know how involved I want to be.”

The next decision is which collaboration style to try. Their preferred balance of control and interruption is still unknown, so choosing an architecture would be premature.

## Try

Show two short walkthroughs of the same task: adding a dry-run flag to a CSV export script.

- **Checkpoints:** the partner asks about the change's scope and an implementation choice before preparing a diff.
- **Delegation:** the partner makes those decisions within the agreed task, then presents the diff and explains its choices.

Both walkthroughs show equally competent work on the same requirements. They differ in when the user participates. They can reveal what the user expects to prefer, but cannot establish how the interaction feels in use or whether automation is reliable.

Suppose the user responds: “I want to approve the scope before it starts, but I don't want questions about every implementation detail.”

## Learn

The user distinguished control over scope from control over implementation. That suggests a third option: agree on scope once, then delegate work within that boundary.

The direction becomes more specific. The original choice between frequent checkpoints and full delegation was incomplete. This reaction supports trying a third style; it does not establish a lasting preference.

## Choose

Prepare a twenty-minute trial on a disposable copy of the script, with one scope checkpoint. The user tries it and reports where they wanted to intervene.

If the checkpoint gives enough control, use that style for the next small task. If surprises remain, adjust what the checkpoint covers. If neither approach feels useful, revisit the use case. If the trial breaks, address that limitation before interpreting the reaction.

Stop comparing styles once there is enough evidence for the next task. Longer-term preference and reliability can remain open until a larger commitment depends on them.
